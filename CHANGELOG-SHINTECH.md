# Genesynth changelog

**Genesynth** is ShinTech's 16BIT groovebox fork of Felucca (OPN2, PSG and PCM8 engines), for personal use. Based on upstream Felucca v1.6.1
(`63f88ec`). Upstream's own release notes are in its wiki.

## Unreleased

### Genesynth name and splash

- The fork is called Genesynth. A new power-on splash in a 16-bit console style (the name in chrome, "16-BIT", the
  credits "ShinTech Electronics" and "based on Felucca · Hügelton Instruments", the version drawn on it at boot)
  replaces upstream's. It is an image generated by `tools/shintech/gen_splash.py` (Pillow, DejaVu Sans Bold) into
  `firmware/src/genesynth_splash.h` (checked in, ~8 KB run-length coded); `tests/ui_render.c` checks that it decodes
  and is what the screen shows.

### Akai MPK mini IV by default

- A new MIDI IN routing, **MPK** (MENU > MIDI > MIDI IN, appended after TRACK), is the default for new projects
  (upstream: CH1-4): as SEL every channel plays the selected track, but channel 10 (the MPK's pads, the GM drum
  channel) plays the first DRUM track. Older projects keep their own setting.
- The MPK mini IV's eight knobs (a User preset: CC 24..31, captured from one) step EDIT 1 / 2's eight macros of the
  track the keys play, relative (set the MPK's Global Menu KnobM to **Rel**): two's complement, faster turns move
  further, no jumps. MIDI LEARN of those CCs still wins. On any routing.
- Captured from the MPK mini IV (User 1): keys and knobs channel 1, knobs CC 24..31, pads notes 36..43 on channel
  10 (Bank A), joystick pitch bend and CC 1. `tests/mpk_test.c`.
- A project saved with MPK opened on upstream Felucca reads an unknown ROUT value.

### Phase 0: build, baseline, decisions
- Forked hugelton/Felucca and hugelton/Felucca-WebApp to ShinobiFPV; upstream remotes are fetch-only.
- Added BUILDING-SHINTECH.md: the Windows 11 / WSL2 build, verified. Stock v1.6.1 builds (felucca.fwsc 610,090 B),
  all host tests pass, and the browser emulator builds and passes its own test.
- Decisions: keep 4 tracks (16BIT layout T1 OPN2, T2 OPN2, T3 PSG, T4 PCM8). One emulated chip driven by register
  writes, each voice owning a chip channel. Chip voices count against their chip's channels, not the global
  8-voice budget. Locks, automation and MIDI LEARN cover the 8 macro values, as with FM6.

### Phase 1: core selection and benchmark
- `firmware/src/chips/opn2.c`: a C port of ymfm's YM2612 path (BSD-3-Clause). It is bit-exact against ymfm itself
  (`tests/opn2_ymfm_test.cpp`: 8 seeds x 400,000 samples of random register traffic on both ports).
- `firmware/src/chips/ym3438.{c,h}`: Nuked-OPN2 1.0.12, vendored unmodified (LGPL-2.1-or-later). It's only built
  into the benchmark firmware. `chips/shim/string.h` supplies its one libc header on the target.
- `FELUCCA_CHIPBENCH=1` builds the device benchmark (`firmware/src/chipbench.c`, the `bench` console command). It
  is off in every other build, and the default build is unchanged (all host tests pass).
- Host benchmark, 6 channels with SSG-EG and LFO: Nuked 1,022 ns per native sample, the ymfm port 370 ns (2.8x).
  With the DAC on: 1,134 vs 340 ns (3.3x).
- `tests/run_shintech.sh`: the fork's own host tests.
- The ymfm port is faster and still bit-exact: register values cached at prepare, the PM phase step recomputed only
  when the LFO value moves, a 1024-entry sine table, silent operators skipped, and clock + output fused per channel
  (`opn2_render`). Host: 370 -> 265 ns per native sample. A channel ymfm doesn't hear (channel 6 under the DAC) must
  not be computed, because its output updates its feedback memory; the exactness test caught that.
- Benchmark v2/v3: duty in 32nds of each block, the script one write a block, `bench c1` (the second core),
  `bench load 1` (typical patches). Flashed with `tools/fm1_install.py` from a Windows venv.

| Core | Load | DAC off | DAC on |
| --- | --- | --- | --- |
| Nuked-OPN2 1.0.12 | worst case (6 ch, SSG-EG + AM + PM everywhere) | 694 % | 697 % |
| ymfm port, first | worst case | 124.8 % | 119.2 % |
| ymfm port, optimized | worst case | 96.9 % | 92.4 % |
| ymfm port, optimized | typical (no SSG-EG/AM, vibrato on 2 ch) | 95.6 % | |
| ymfm port, optimized, on core 2 | worst case | 91.6 % | |

- FX sends fed with the chip: +1 % total (the chorus, delay and reverb buses always run).
- Core 2 on this unit: stable for 2+ minutes (no bad job reads, no stalls, no late audio, wait max 542 us). Felucca's
  dual-core split is synchronous (core 1 waits for core 2 each block), so the chip on core 2 still counts against the
  block deadline.
- Neither core left 25 % headroom for 6 FM channels at this point. Decision: optimize the ymfm port further (still
  bit-exact) and use the second core too.

#### Phase 1, round 2: the port on two cores
- `bench cal` measured the CPU (~220-240 MHz, about one simple instruction a cycle). A dependent load costs 4-6
  cycles, the pool is ~25 % slower than `.bss`, and RAM code is no faster than warm XIP.
- The per-sample calls and their 12-register saves cost ~19 % of a core with no note playing. The port now renders
  in blocks (`opn2_render_n`, `opn2_generate_n`), checks `prepare` inline, and inlines the envelope / SSG-EG / LFO.
- `opn2_t` now holds the operators first and `reg[]` last (short load offsets: -8 %), each channel's operators
  together, a 64-byte op struct, and a precomputed `idle` flag.
- Channel-major blocks (`opn2_block_begin` + `opn2_block_channels`): a block's global steps first, then each channel
  over the block. So channels can render apart: `opn2_begin_n` / `opn2_channels_n` / `opn2_mix_n` split the six
  channels across the two cores (4..6 on core 2, started before the parts; 1..3 on core 1 after them).
- Every step stays bit-exact against ymfm. The test now also renders random block sizes and the two-core split.
- `.fast_text` (app.ld, build.py, main.c): hot DSP code copied to RAM at boot; it may call into XIP (`OPN2_FAR`).
  `fm1_guard.h`'s PC limit now ends at `_ft_end`. Its first version missed that, and the FM-1 crashed; a second
  crash within 30 s of boot (the console script restarting the benchmark) sent it to UBOOT, and a power cycle brought
  it back. The console scripts (`tools/shintech/`) now stop at the first reboot or lost port.
- Tried and dropped: per-operator block loops (slower here: the state stays in memory, the arrays add traffic).

| ymfm port, % of one core at full time | worst case | typical |
| --- | --- | --- |
| core 1 alone (round 1 best) | 93.6 % | 86.7 % |
| core 1 alone (channel-major blocks) | 84.1 % | 80.2 % |
| **split, 3 + 3 channels: the whole ISR (idle 13 % included)** | **54 %** | **50 %** |

- Split, worst case at full time: core 1's part 43.6 %, core 2's 35.8 %. A 60 s soak: no late buffer, no core-2
  fault, the longest half 1,997 us of 2,902 (69 %).
- **Choice: the ymfm port (BSD-3-Clause, in C), split across both cores. Nuked-OPN2 (694 %) is out.** Without the
  second core (MENU > SYSTEM > 2ND CORE OFF, or a unit that cannot run it) the port alone costs ~84 % worst case; the
  engine must then cap the sounding FM channels (Phase 2).


### Phase 4: the PCM8 track

- Engine 16, PCM8 (`firmware/src/eng_pcm8.c`): the console's 8-bit DAC as drivers used it, a few voices mixed in
  software into one DAC. Its sounds are Felucca's own, **nothing new in flash** (the image keeps ~30 KB free, the RAM
  pool unchanged): SRC STD 80 10 66 55 77 DEEP TIGHT PERC (DRUM's synthesized kits, the GM key map), BREAK (SLICE's
  loop, its hits as slices), USR1..USR3 (a user slot sliced by SLICE, its AUTO onsets or MAN slices, one hit per slice
  in GM order on the keys: 36 kick, 38 snare, 42 closed hat, 46 open hat, 39 clap, 45 low tom, 50 high tom, 49 crash,
  37 rim, 51 ride, 56 cowbell, 54 tambourine). A voice is the source engine's own voice, called with PCM8's values in
  its places; after the part's voices (a new optional `engine_t.post`) the mix goes through the DAC: sampled and held
  at RATE 12 / 24 / 48 kHz, rounded to BITS 8 or 4, the ladder step away from zero (LADR), LGCY CLEAN / EARLY / LATE.
  MODE 3 VOICE or 1 SHOT (one stream). 14 presets. An EDIT panel draws a sine through the DAC as set.
- **Sample slots: the three user slots that exist** (0xA0000..0xDBFFF, 80 KiB each, ~7 s of 22.05 kHz ADPCM, shared
  with SAMPLE, GRAIN and SLICE), filled with the editor's existing upload, recording and trim. The flash map has no
  other free sectors; more slots would mean taking the projects', the user presets' or the OTA staging's room, which
  this fork does not do (stability first). A slot holds a whole kit as a row of hits (SLICE finds up to its AUTO
  count of onsets).
- With a PCM8 track in the project OPN2 has five FM channels: channel 6 is the DAC, as on the console.
- Stores: as OPN2's and PSG's (FUNB, version 6 presets, favourites in row 3's upper half). Last in the engine order.

#### Device test (FM-1, 2ND CORE ON, HALL reverb; the console's new `clr` resets the peak for each case)

| case | longest half (of 2,902 us) | voices shed |
|---|---|---|
| PCM8 hits alone / the stock DRUM's | 1,181 / 1,073 us | 0 |
| OPN2 x6 + PSG x3 | 2,002-2,069 us (~70 %) | 0 |

### Phase 3: the PSG engine

- Engine 15, PSG (`firmware/src/eng_psg.c` over `chips/psg.c`, our own SN76489-class chip, register-driven: latch /
  data bytes as on the chip). One shared chip, 3 tone channels and the noise channel, owned by the voices of the PSG
  tracks (CHIP LIMIT as OPN2's). Noise white or periodic, at the chip's three rates or tracking its note through
  tone 3 (which it then takes, silenced, as on the chip). The shift register SEGA 16-bit (the default) or TI 15-bit.
- Volume in the chip's 16 levels (2 dB steps): the track's ADSR and velocity rounded to them each block, or DRV 1..15,
  a driver's stepped decay (a step every DRV frames). ARP (11 chords), its speed, VIB (after a delay) and SWP, all in
  60 Hz frames. A mild high-pass (~55 Hz) on each channel (the chip's output is unipolar).
- WAVE, 11 shapes: the chip's SQUARE, WHITE and PERIOD (the card reads **WAVE**; the panel **AUTHENTIC**), and the
  extension's PLS 25 / 12 / 6, SAW, TRI, R-SAW (ramps on the chip's own volume levels, as fast volume writes make them)
  and METAL / BUZZ (short noise sequences) (the card reads **WAVE+**; the panel **EXTENDED**).
- 26 original factory presets in 7 categories. EDIT 1's panel draws the wave from the chip's levels; EDIT 2's (MACROS)
  one second of the driver: the pitch the macros make and the volume DRV steps.
- The render steps each channel a flip at a time (one or two steps a sample instead of five or six ticks), equal to
  tick by tick sample for sample (`tests/psg_engine_test.c`), and runs on the second core with OPN2's channels 4..6.
- Stores: as OPN2's (FUNB projects, version 6 user presets, favourites in row 2's upper half). Last in the engine order;
  the EDIT layer's shared key goes DRUM -> OPN2 -> PSG.

#### Device test (FM-1, 2ND CORE ON, HALL reverb)

|---|---|---|

### Phase 2: the OPN2 engine

- Engine 14, OPN2 (`firmware/src/eng_opn2.c`): one shared chip, 6 channels owned by the voices of the OPN2 tracks
  (CHIP LIMIT steals the oldest released, else the oldest held), POLY / MONO / LEGATO, RATIO, CH3 mode, velocity to
  the carriers' TL, the ladder and Legacy shaping (CLEAN / EARLY / LATE, with or without S&H), channels 4..6 on the
  second core. 32 original factory patches in 7 categories (`opn2_factory.h`). Last in the engine order; on the EDIT
  layer the 13th white key cycles DRUM -> OPN2.
- Stores: a project with a track on an engine >= 14 is written FUN11 ("FUNB"), any other still FUN10 ("FUNA"), as
  upstream; both load. **A FUNB project does not open on upstream Felucca.** User presets of an OPN2 sound are
  version 6 records. Favourites of engines >= 14 live in the unused upper halves of favourites rows 0 / 2 / 3.
- `op2_mix_begin` / `op2_post` are kept out of the audio ISR (their own target budgets, `tests/target_budget.txt`).
- The chip is not clocked while it is silent (no note, every operator released to full attenuation, no write
  pending): an OPN2 track that plays nothing costs nothing. A note after such a pause differs from one on a chip
  clocked meanwhile only by the envelope counter's phase at its key on (as on the chip, where it runs free).
- Without the second core (2ND CORE OFF, or it gave up) notes take channels 1..3 only (`OP2_ONE_CORE_CAP`); the
  notes past it end when it gives up mid-play.
- Console `status`: `opn2_c1_blocks`, `opn2_c1_failed`, `opn2_idle_blocks`, `opn2_busy`, `opn2_nchan`.

- On-device editing: the OPERATOR, OP ENV and OPERATOR 2 pages for an OPN2 track (`ui_opn2op.c`): OP 1..4, MUL /
  RATIO, DT / FINE, TL; the envelope stage's AR / DR / SR / RR and SL; DT, KS, AM. They write the track's own patch
  (SLOT OWN), one undo per gesture (undo now keeps the OPN2 patch). The algorithm chart (the YM2612's eight, with
  the operator or the macro turned in the accent) on those pages and on EDIT 1 / 2; the envelope drawn in dB with
  the other three operators behind it. SSG-EG and CH3 offsets: the web editor's.
- Patch files: `.tfi`, `.vgi`, `.dmp` (DefleMask v2..11, OPN2 / Genesis systems) and `.fui` (Furnace "FINS" FM) import
  into the 96-byte patch, and `.tfi` exports, in the web app (`Felucca-WebApp` `app/src/opn2.js`, its 18 unit tests
  `test_opn2.mjs`); the editor's page that uses them is Phase 5's.
- The browser emulator (`web/emu`) builds with OPN2 and passes `emu_test.mjs`, now with an OPN2 song (two OPN2
  tracks of chords on the shared chip and the drums: it sounds, the same samples twice, 2.0 % of real time on the
  build PC) and the boot waits for the ~3 s splash; the native build (`native_check.c`) still equals it bit for bit.
- Credits: MENU > ABOUT / CREDITS lists Genesynth, ymfm (BSD-3-Clause) and the splash's DejaVu lettering first;
  `CREDITS.md` and `LICENSING.md` too.

#### Known limitations (Phase 2)

- **Mono chip channels:** each channel's L / R output bits (register B4) are read as one: a channel heard on L, R or
  both sounds in the middle, and the track's PAN places it. Per-channel hard panning as on the chip is not modelled.
- **CHIP LIMIT is always on:** a seventh note takes a channel (the oldest released, else the oldest held). There is
  no "CHIP LIMIT OFF" (more than six notes would need a second chip: twice the CPU, over the budget).
- The one-core cap (3 channels) applies whenever the second core is not answering.

#### Device test (FM-1, 2ND CORE ON, HALL reverb; `tools/shintech/fm1midi.py` + console `status`)

| state | cpu_pct | longest half (of 2,902 us) |
|---|---|---|
| no OPN2 track (ANALOG) | 13 % | 771 us |
| OPN2 track, 1 note (PAD) | 47 % | 1,578 us |
| 6 notes (every channel) | 64 % | 2,189 us (75 %) |
| 8 notes held (CHIP LIMIT steals 2) | 63 % | - |
| T1 PAD 3 + T2 BRASS 3 | 62 % | - |
| released (tails) | 54-57 % | - |

No late blocks, no reboot, the second core took every block (`opn2_c1_blocks` +1,378/s, `opn2_c1_failed` 0).

With the chip unclocked while silent (same test): OPN2 tracks with no notes 14 % (46-54 % before: the chip ran
whenever a track was OPN2), 1 note 35 %, 6 notes 64 % with the longest half 2,082 us (72 %); idle again within 9 s
of the PAD's release.

One core (2ND CORE OFF, ORGAN F14, `opn2_busy` from the console): a cap of 4 held 4 channels but took the longest
half to 2,539 us (87 %, 72 % CPU): over the 75 % line. **The cap is 3:** 3 notes 61 % CPU, the longest half 2,099 us
(72 %); 4, 6 and 8 notes held keep 3 channels (the rest stolen), all free after the release, no late block, no
reboot.
